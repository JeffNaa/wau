Wau Core 文档

高灵活度、插件化开发平台。内核稳固，业务动态。

项目介绍

Wau（月亮风筝）是一个基于 NestJS 构建的高灵活度、插件化开发平台。核心理念是 "内核稳固，业务动态"：

  • 隔离变更：所有业务逻辑封装在插件中，核心系统永不为特定需求做硬编码。
  • 即插即用：通过 .zip 动态加载，实现功能的秒级安装与卸载。
  • SDUI Ready：UI 布局由后端协议驱动，修改界面元素仅需调整 JSON，无需重新发布 App。
  • 原子化解耦：插件之间通过事件总线通信，既能协同工作，也能彻底拆分。

核心特性

🔌

插件管理

支持通过 Dashboard 动态上传并解压缩插件包，服务器自动重启加载新插件路由。

🔄

动态路由注入

插件包解压缩后，内核自动扫描并注册其定义的 API 路由，并自动添加路由前缀。

🗃

扩展性数据模型

采用 PostgreSQL + JSONB 架构，允许插件存储私有的元数据而不改动核心表结构。

📋

JSON Schema

插件通过 manifest.json 声明表结构，核心自动创建并同步 PostgreSQL 表。

🔃

SQL 迁移

插件可携带 .sql 迁移文件，核心跟踪并增量应用，支持回滚。

🗣

i18n 国际化

插件响应消息、Schema、KV 存储及错误处理已全面本地化，支持自动语言回退。

🔒

认证与授权

内置基于令牌的认证系统，支持角色权限控制与通配符匹配。

📱

跨端协议

通过统一的 JSON 协议驱动 Flutter 和 Web 端渲染，一套后端多端适配。

前置要求

  • PostgreSQL 14+ 正在运行且可访问
  • Node.js 20+ 与 npm
  • .env 文件包含有效的 DATABASE_URL

快速上手

# 1. 安装依赖
npm install

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 设置 DATABASE_URL

# 3. 初始化数据库
npx prisma migrate deploy

# 4. 生成 Prisma 客户端
npx prisma generate

# 5. 启动开发服务器
npm run start:dev

# 6. 服务器运行在 http://localhost:3000
#    插件存储在 ./storage/plugins/
💡 首个用户 = 管理员
第一个注册的用户自动获得 ADMIN 角色与 ["*"]（全部）权限。后续用户获得 USER 角色，默认无权限。

1. PrismaModule src/prisma/

标记为 @Global()，因此 PrismaService 可以在任何地方注入，无需显式导入。

  • 通过 pg.Pool 从 DATABASE_URL 创建 PrismaClient，使用 @prisma/adapter-pg 适配器。
  • 实现 OnModuleDestroy，在关闭时优雅断开连接。
  • 暴露 client 属性直接访问模型（无仓库模式）。
  • 提供 query(sql, params?) 方法通过 pg pool 执行原始 SQL。

2. PluginLoaderModule src/plugins/

一个带有静态 forRoot(pluginsDir) 工厂方法的动态模块。在应用启动时运行，扫描文件系统。

  • 枚举 storage/plugins/<name>/dist/index.js，若不存在则回退到 index.js
  • 使用 Reflect.getMetadata('controllers', PluginModule) 检测控制器路径
  • 以 manifest name 为前缀自动拼接路由（如 /test-plugin/status）
  • 检测并拦截跨插件重复的控制器路由
  • 读取 manifest.auth，当 auth.required === false 时应用 isPublic 元数据
  • 将有效插件模块导入 NestJS 模块图
⚠️ 基于文件系统
由于该模块在静态工厂中运行，无法以数据库作为数据源。插件安装/更新/卸载后，服务器会自动重启以重新加载路由。

9. I18nModule src/i18n/

标记为 @Global()，I18nService 可在任何地方注入。对所有路由应用 I18nMiddleware，读取请求的 Accept-Language 头，通过 AsyncLocalStorage 将解析出的 locale 绑定到当前请求作用域。默认 locale 为 en。

核心 locale 文件存放在 locales/{locale}/*.json。插件在安装时注册各自的翻译，在卸载时注销。

认证与授权概述

Wau Core 包含一套完整的基于令牌的认证和基于角色的授权系统，从零构建（不依赖 Passport 或 JWT 等外部库）。两个全局守卫作为 APP_GUARD 注册在 AppModule 中：

  • AuthGuard — 在每个请求上验证 Bearer 令牌（除非标记了 @Public()）
  • PermissionGuard — 检查标有 @RequirePermissions() 的路由所需权限

AuthService src/auth/auth.service.ts

核心认证逻辑，实现基于令牌的认证与 bcrypt 密码哈希。

主要特性

  • 基于令牌的认证：创建 32 字节随机十六进制令牌，存储在 userToken 表中，可配置 TTL（默认 7 天）
  • 自动清理：每 6 小时执行一次定时任务，清理过期/已撤销的令牌
  • 首个用户为管理员：第一个注册用户获得 ADMIN 角色和 ["*"] 权限
  • 角色同步：启动时确保 ADMIN 和 USER 角色具有正确的权限

方法

方法说明
register(dto)创建新用户并哈希密码。首个用户成为 ADMIN。
login(dto, ip?, userAgent?)验证凭据，检查 ACTIVE 状态，清理过期令牌，更新 lastLoginAt，返回令牌。
validateToken(token)若令牌有效且未过期/撤销，返回包含角色和权限的 UserPayload。
revokeToken(token)将令牌标记为已撤销。
revokeAllTokens(userId)撤销用户的所有有效令牌。
getMe(userId)返回当前用户详情及权限（password 已省略）。
changePassword(userId, dto)验证旧密码，哈希新密码，撤销所有令牌。
forgotPassword(email)生成重置令牌（1 小时有效期），存储在用户 profile 中。返回通用响应。
resetPassword(token, newPassword)验证重置令牌，更新密码，撤销所有令牌。

AuthController API src/auth/auth.controller.ts

/auth 下的 REST 接口。标记 @Public() 的路由绕过认证。

POST /auth/register

公开 — 注册新用户。首个用户成为管理员。

请求体: { email: string, password: string (最少6位), name?: string }

响应: { user: { id, email, name }, token: { token, expiresAt } }

POST /auth/login

公开 — 认证并获取令牌。

请求体: { email: string, password: string }

响应: { user: { id, email, name }, token: { token, expiresAt } }

POST /auth/logout

撤销当前令牌（从 Authorization 头中提取）。

响应: { message: "登出成功" }

POST /auth/logout-all

撤销当前用户的所有令牌。

响应: { message: "所有会话已登出" }

GET /auth/me

获取当前用户详情及权限。

响应: { id, email, name, status, role, permissions, ... }

PUT /auth/password

修改密码。修改后所有令牌将被撤销。

请求体: { oldPassword: string, newPassword: string (最少6位) }

POST /auth/forgot-password

公开 — 请求密码重置令牌。SMTP 尚未实现 — 目前重置令牌直接在 API 响应中返回。

请求体: { email: string }

无论邮箱是否存在都返回相同的通用消息（防止枚举攻击）。

POST /auth/reset-password

公开 — 使用有效的重置令牌重置密码。

请求体: { token: string, newPassword: string (最少6位) }

插件 Auth 元数据

插件可以在 manifest.json 中声明认证配置：

{
  "name": "my-plugin",
  "version": "1.0.0",
  "auth": {
    "required": false
  }
}

当 auth.required === false 时，PluginLoaderModule 自动将插件控制器上所有路由处理方法标记为 isPublic: true，使其绕过 AuthGuard。

⚠️ 权限仅为信息性
manifest.auth.permissions 被核心有意忽略。manifest.json 中声明的权限纯粹是信息性的。实际的权限执行需要在每个路由处理器上显式使用 @RequirePermissions(...) 装饰器。

插件结构

一个有效的 Wau 插件是一个 ZIP 压缩包，结构如下：

my-plugin.zip
├── manifest.json          # 插件元数据
├── dist/
│   └── index.js           # 插件入口文件（若不存在则回退到根目录 index.js）
├── locales/               # 可选：i18n 翻译文件
│   ├── en/
│   │   ├── messages.json
│   │   └── errors.json
│   └── zh-CN/
│       ├── messages.json
│       └── errors.json
└── migrations/            # 可选：SQL 迁移文件
    └── 20260101000000_init.sql

manifest.json

必需字段：name、version。其余均为可选。

{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "插件描述",
  "author": "作者名称",
  "auth": {
    "required": true,
    "permissions": ["plugin:read"]
  },
  "i18n": {
    "defaultLocale": "en",
    "locales": ["en", "zh-CN", "ms-MY"],
    "path": "./locales"
  },
  "schema": {
    "articles": {
      "title":   { "type": "string", "required": true, "i18n": true },
      "content": { "type": "text",   "i18n": true },
      "slug":    { "type": "string", "required": true, "unique": true, "length": 100 },
      "status":  { "type": "string", "required": true, "default": "draft", "index": true }
    }
  }
}
字段必需说明
name是插件唯一标识符，用作路由前缀和表名前缀。
version是语义化版本号。安装时拒绝相同版本或降级上传。
description否可读描述。
author否作者名称。
auth否认证元数据。required: false 使所有插件路由公开。
i18n否声明 i18n 支持。defaultLocale、locales、path（默认 ./locales）。
schema否JSON schema，用于通过 PluginSchemaService 动态建表。

i18n（多语言翻译）

若解压后的插件包含 locales/ 目录，核心会在安装/更新时自动调用 I18nService.registerPluginLocale()，在卸载时调用 unregisterPluginLocale()。

Locale 文件为纯 JSON，路径格式为 locales/{locale}/{file}.json。支持两种布局：

// 平铺布局
{
  "welcome": "欢迎！",
  "created": "创建成功。"
}

// 包裹布局（唯一顶层 key 与文件名一致时自动展开）
{
  "messages": {
    "welcome": "欢迎！",
    "created": "创建成功。"
  }
}

两种方式均可通过 i18n.tPlugin(pluginName, 'messages.welcome') 访问。占位符插值使用 {key} 语法。

JSON Schema

在 manifest.json 中声明 schema 对象，由 PluginSchemaService 自动创建并同步 PostgreSQL 表。表名前缀为 plugin_{name}_{model}。

在任意字段上添加 "i18n": true 可将其存储为 JSONB locale 映射。通过 find() / findOne() 读取时，自动返回当前请求 locale 对应的扁平值。

SQL 迁移

插件可包含 migrations/ 目录，存放以可排序时间戳前缀命名的 .sql 文件。安装/更新时按字母顺序执行，执行记录在 plugin_registry.migrations_applied 中防止重复执行。卸载时自动删除前缀为 plugin_{name}_* 的表。

构建与打包

将 TypeScript 编译到 dist/，并从入口文件导出 NestJS 模块类：

// dist/index.js（由 index.ts 编译生成）
export { MyPluginModule } from './src/my-plugin.module';

ZIP 中应包含 manifest.json、dist/，以及可选的 locales/ 和 migrations/。不要打包 TypeScript 源文件、node_modules 或构建配置文件。

插件管理 API

GET /plugins

权限: plugin:read

从数据库列出所有已安装插件。

响应: { name, version, description, author, manifest, migrationsApplied, createdAt, updatedAt }[]

POST /plugins/upload

权限: plugin:create

请求体: multipart/form-data，字段 file（ZIP）

插件不存在时全新安装；上传版本更高时自动更新；相同版本或降级被拒绝。

响应（安装）: { success, plugin, version, path, message }

响应（更新）: { success, plugin, previousVersion, version, path, message }

PUT /plugins

权限: plugin:update

请求体: multipart/form-data，字段 file（ZIP）

更新已安装插件。插件名称从 ZIP 的 manifest.json 自动检测。验证和行为与 upload 在插件已存在时相同。

DELETE /plugins/:name

权限: plugin:delete

按名称卸载插件。清理 schema 表、迁移和 plugin_data 条目。

响应: { success, plugin, message }

数据库模型

文件：prisma/schema/schema.prisma（generator & datasource）+ prisma/schema/plugin.prisma + prisma/schema/auth.prisma

PluginRegistry

model PluginRegistry {
  id                String   @id @default(cuid())
  name              String   @unique
  version           String
  manifest          Json
  migrationsApplied Json?    @map("migrations_applied")
  createdAt         DateTime @default(now()) @map("created_at")
  updatedAt         DateTime @updatedAt @map("updated_at")

  @@map("plugin_registry")
}

PluginData

model PluginData {
  id        String   @id @default(cuid())
  plugin    String
  key       String
  data      Json
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  @@unique([plugin, key])
  @@index([plugin])
  @@map("plugin_data")
}

Role

model Role {
  id          String   @id @default(cuid())
  name        String   @unique
  permissions Json?    @default("[]")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @updatedAt @map("updated_at")

  users User[]
  @@map("roles")
}

User

model User {
  id          String     @id @default(cuid())
  email       String     @unique
  password    String
  name        String?
  avatar      String?
  status      UserStatus @default(ACTIVE)
  roleId      String     @map("role_id")
  role        Role       @relation(fields: [roleId], references: [id])
  profile     Json?      @default("{}")
  lastLoginAt DateTime?  @map("last_login_at")
  createdAt   DateTime   @default(now()) @map("created_at")
  updatedAt   DateTime   @updatedAt @map("updated_at")

  tokens UserToken[]
  @@map("users")
}

UserToken

model UserToken {
  id        String    @id @default(cuid())
  token     String    @unique
  userId    String    @map("user_id")
  user      User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  expiresAt DateTime  @map("expires_at")
  revokedAt DateTime? @map("revoked_at")
  ip        String?
  userAgent String?   @map("user_agent")
  createdAt DateTime  @default(now()) @map("created_at")

  @@index([userId])
  @@map("user_tokens")
}

UserStatus 枚举

enum UserStatus {
  ACTIVE
  DISABLED
  PENDING
  @@map("user_status")
}

Prisma 配置与部署

Wau Core 基于 Prisma 7，使用 @prisma/adapter-pg 适配器连接 PostgreSQL。Schema 拆分在 prisma/schema/ 下的多个文件中。

常用命令

命令用途
npx prisma migrate dev --name <name>开发时创建新的迁移并在本地应用
npx prisma migrate deploy应用待执行的迁移（生产 / CI）
npx prisma migrate status查看迁移历史与数据库状态
npx prisma generateSchema 变更后重新生成 Prisma 客户端
npx prisma studio通过本地 GUI 浏览数据

生产部署

# 1. 应用待执行的迁移
npx prisma migrate deploy

# 2. 生成客户端
npx prisma generate

# 3. 构建并启动
npm run build
npm run start:prod
💡 核心迁移 vs 插件迁移
核心 Prisma 迁移只负责 plugin_registry、plugin_data、users、roles 和 user_tokens 表。插件自有的表是在插件安装时由 PluginSchemaService（基于 manifest.json 中的 schema）和 PluginMigrationService（基于 migrations/*.sql）创建的。这两套系统相互独立。

未来路线图

Wau 的定位是一个全栈插件化平台。后端核心只是起点：

  • Flutter 客户端（wau-flutter） — 一个移动端 App 壳，能够根据插件下发的 JSON 协议动态渲染页面。
  • React JS Web 应用（wau-web） — 既是面向管理员的后台管理端，也是面向终端用户的客户端。
  • 事件总线（Event Bus） — 跨插件通信机制，让后端插件能无缝触发 Flutter 和 Web 端的行为。
  • SDUI 协议 — 后端驱动布局引擎，实现完全动态化的 UI 生成。
